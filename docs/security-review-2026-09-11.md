# 协议安全复查与修复记录（2026-09-11）

本轮在上一轮修复基础上，检查恶意请求、并发写入、重放、服务端已完成但客户端丢失响应，以及种子恢复。以下区分已经实现的防护与尚未消除的协议边界；测试通过不代表协议已经没有漏洞。

## 已实现

|---|---|
| 随便填写交易引用即可买凭证 | 默认拒绝付款；可信 PaymentVerifier 必须校验结算、收款方、金额和盲请求的付款承诺。测试验证未配置适配器时不签名、不消耗交易引用。 |
| 低价签名兑换高价隐藏权益 | 按价格使用独立密钥，兑换时按已签名 claim 的价格选择验证密钥。测试覆盖支付一单位、隐藏 255 个月 premium claim。 |
| 客户端伪造日期抢占未过期名称 | 有效期和宽限期使用服务端时钟；客户端日期提示不参与授权。覆盖 u32::MAX 提示、宽限边界和加法溢出；溢出不消耗凭证。 |
| 名称转移重放、并发抢注/续费覆盖 | 当前名称记录携带随机 nonce；注册和转移更换 nonce，签名包含 nonce。服务操作串行化。覆盖 A→B→A 重放和两名并发注册者只有一个成功。 |
| 付款响应丢失 | 同一交易、金额、盲请求返回原盲签名；不同请求不能再使用该交易。 |
| 恶意服务端返回能解密但地址不匹配的替代媒体 | 客户端同时核对 kind 和媒体地址，再解密；覆盖用已知原文件密钥生成另一份有效 AEAD 的攻击。 |
| 房间块占据媒体地址 | 地址最高位区分媒体/房间；服务端校验类型位及媒体哈希。房间 ciphertext 不能占媒体地址。 |
| 重复上传同一文件丢失第一张收据 | 上传账本按 receipt 区分；逐张释放。覆盖重复上传、种子恢复、两次退款以及最终释放媒体。 |
| 上传/退款的响应丢失导致永久损失 | 在加密 keyring 内保存操作及 unblinding 状态；各服务记录原响应并约束精确重试。覆盖丢失 Put/Release 响应后销毁客户端、从种子恢复并完成原操作。提款失败批次不扣款，精确重试只扣一次。 |
| 退款重放产生重复额度 | 重复兑换只对原账户返回成功，不重复记账；其他账户拒绝。释放收据时，只允许相同盲请求重取原结果。 |
| 删除房间块后收据无法退款 | 删除 ciphertext 时保留收据计数，最后一张收据释放后清理；不允许重建内容绕过旧账目。 |
| 旧设备覆盖房间、收据或联系人撤销 | 写快照携带预期 snapshot hash 和 delta count，服务端 CAS；收件许可和快照同一操作更新。覆盖旧设备写入拒绝、撤销后旧设备不能重新发布旧许可。 |
| 长缺口后永远找不到后续消息 | 有限前向扫描跨调用推进；单独回查固定区间中的旧缺口。覆盖连续隐藏多个旧消息，随后恢复可见且完整找回。 |
| 恶意 ciphertext 导致整个同步中止 | 验证失败的条目不进入历史和排序；继续处理其他位置。网络故障仍明确返回。 |
| 恢复时静默丢弃坏 delta / MLS 状态 | 格式或验证失败明确报错；不会把损坏数据当成正常空状态。 |
| 多 lane 大历史导致平方级排序 | 同 lane 前驱链、每个 clock lane 仅保留最后已见前驱；索引和有序 ready 集处理依赖与循环。复杂度随实际历史和 clock 输入增长；覆盖 16,384 条跨 lane 历史、极值序号和循环。客户端拒绝 roster 外的 clock lane。 |
| 空连接与 slow-drip 占住工作线程 | 每监听器最多 128 个连接；TLS/WebSocket 握手绝对时限 15 秒，完整帧时限 90 秒（允许默认 60 秒 cover 间隔）。每次小读不重置期限；WebSocket 单帧及组装消息上限均为 16 MiB。 |
| 生产鉴权时钟永久停在 1 | 默认使用真实服务端分钟时钟；固定时钟只由可信测试配置注入。 |

客户端新增 `retry_pending_upload`，Session 和 FFI 均已暴露；CLI 为 `retry-upload PROFILE`。该操作续办原发送，不创建新消息。存在未完成上传时不能开始另一笔发送。快照冲突需要重新打开账户，不能强行覆盖。

## 本次继续修复

- 服务端改用 SQLite WAL/FULL；授权消费、计费和幂等响应在同一事务提交后确认。测试覆盖事务放弃回滚、独立连接竞争只扣一次，以及真实 CLI 服务被 kill 后恢复历史并继续发送。
- 所有已配置的存储/退款 denomination 密钥、价格密钥、轮换历史、challenge secret 和 TLS identity 持久化。服务目录 0700、数据库 0600，拒绝符号链接；同部署目录使用进程锁。重启测试验证 pin、账户和消息保持不变。
- 网络 Auth 签署完整请求和随机 nonce；替换操作、contacts 正文、nonce，以及并发/重启重放均拒绝。服务时间下限持久化，时钟回拨不能复活已经清理的证明。每分钟最多接纳 65,536 个鉴权请求，避免重放表无限增长。
- 按账户读取 delta/inbox 改为数据库索引范围查询，避免扫描其他账户；Db::open 在创建密钥文件前检查私有父目录。
- 多 lane 排序、slow-drip 时限及 WebSocket 大消息限制见上表。原有非相关依赖版本已保留，仅添加 SQLite 所需依赖。

## 部署条件与未消除的边界

1. **真正的链上结算适配器尚未实现。** 默认部署拒绝所有 Purchase。价格密钥已经持久化；仍须根据选定链实现可信支付验证并配置价格表，不能把测试用 TestPayments 用于生产。
2. **恶意房间成员仍能抢占其他成员的日志位置。** 所有成员都能从共享 root 算出位置；存储端不知道谁有该位置的写权限。现在不能伪造作者、不能阻断其他位置的读取，但目标消息的可用性仍会受影响。彻底解决需要可由服务端验证、又不暴露稳定成员标识的写授权协议，不能靠 contacts 或客户端签名检查消除。当前没有声称解决这一点。
3. **恶意服务器仍可拒绝服务、隐瞒 ciphertext 或回滚整个账户。** 有限扫描改善暂时缺口，CAS 阻止诚实服务器上的旧客户端覆盖，但都不构成对恶意服务器的完整性或新鲜度证明。种子恢复没有独立的最新状态锚点。
4. **全局容量与 Sybil / DDoS 边界仍存在。** 单连接、帧大小、重放窗口和排序开销已有约束，但大量合法身份仍可能耗尽部署容量；需要与实际容量和账户准入经济模型匹配的运营控制。限流不能证明可用性。

网络入口使用严格的 `handle_wire`；底层 `handle` 仍是可信进程内测试接口，不是供代理或网络调用的认证协议。没有增加旧 wire Auth 的兼容通道。
